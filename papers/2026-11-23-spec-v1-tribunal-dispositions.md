## Consolidated Dispositions

### 1. Daemon Lifecycle, Locking, Upgrades & OS Hygiene

| Finding (Reviewers) | Root Cause in v1 | v2 Disposition |
| --- | --- | --- |
| **Infinite `BUILD_DIGEST` A/B/A respawn war & `<current_exe>` loop** (All 5: Kimi C1, GPT C7, Claude C1, GLM C1, 10th C1) | Equal-digest requirement let an old running `mcp` shim kill a newly upgraded daemon and respawn `<current_exe>` (which is already the new binary on macOS or `(deleted)` `ENOENT` on Linux); two installs on `PATH` ping-ponged forever; `LC_UUID` was nondeterministic. | **FIXED.** Decoupled `IPC_SCHEMA_VER` compatibility from deterministic `build.rs` `BUILD_DIGEST` + monotonic `BUILD_ORDER`. Compatible builds coexist cleanly. **`mp-outpost mcp` NEVER kills a running daemon** (on incompatible newer schema, returns crisp `daemon_schema_newer_restart_mcp`). Only explicit `mp-outpost daemon restart` or a strictly newer CLI on schema mismatch drains/replaces (verifying on-disk exe matches before draining). Read-only `daemon status`/`logs` never drain. |
| **Clients murdering healthy daemons on 1.5s `Hello` timeout & unsafe numeric `kill()`** (Claude C9, GPT H1, Kimi H2, GLM H1, 10th C3) | Swap/laptop-wake/debugger caused a 1.5s `Hello` timeout to trigger `SIGTERM`/`SIGKILL`; Linux `/proc/<pid>/stat` field 22 (jiffies since boot) was compared against wall-clock `pid_start_time_ns`. | **FIXED.** Clients never signal a daemon on a slow `Hello`; wedge detection belongs solely to the daemon's own watchdog. Only explicit `daemon stop --force` escalates using Linux `SO_PEERPIDFD` + `pidfd_send_signal` or same-API native start-time comparison (`proc_pidinfo(getpid())` on macOS, raw `/proc/self/stat` field 22 on Linux, zero wall-clock conversion) + `fcntl(F_GETLK)` diagnostic check. |
| **Split-brain runtime dirs (`$XDG_RUNTIME_DIR` vs `/tmp`), temp-file reapers, `umask(0177)`, `sun_path` math bug, idle-exit lock release & zombies** (All 5: Claude C10/H11/M2/M10, GPT C6/H2/H3, Kimi H1/H3/H4/H10, GLM M2/M3/M10, 10th C3/H5/M2/M3/M4) | `$XDG_RUNTIME_DIR` varies between desktop & SSH; `/tmp` is reaped by `tmpfiles.d`; `umask(0177)` strips owner `+x` on `mkdir(0700)`; `d.sock.tmp.<16hex>` was +21 B (109 B > 103 B); idle exit released `startup.lock` 2s before `daemon.lock`; `"already_running"` broke binary readiness pipe; un-reaped daemon left zombies; Node/Electron hosts leak non-`CLOEXEC` FDs. | **FIXED.** (1) Derive runtime dir by UID only: Linux `/run/user/<uid>/mpo/d<13hex>/` (if owned `0700`), else `$HOME/.cache/mpo/d<13hex>/` (no `/tmp` fallback); macOS `confstr(_CS_DARWIN_USER_TEMP_DIR)` + `/mpo/d<13hex>/` with `t.<8hex>` temp name (`<= 88 B <= 103 B`). (2) Watchdog checks `(st_dev, st_ino)` of dir, `daemon.lock`, and `d.sock` every 5s and self-fences on unlink/reap. (3) Set `umask(0077)` once before threads; daemon unlinks stale `d.sock`/`t.*` under `daemon.lock`, `chmod(0600)`, `link(tmp, d.sock)` (direct-bind fallback on `EOPNOTSUPP`). (4) Atomic `Serving -> Draining -> Exited` holding `startup.lock` until `_exit`. (5) Unified binary readiness pipe (`0x00` ok+epoch, `0x01` err+utf8, `0x02` already_running), `dup2(pipe_w, 3)` + `POSIX_SPAWN_CLOEXEC_DEFAULT` / `close_range(4, MAX)`, double-fork to prevent zombies. (6) Mandatory `Hello` within 5s of accept. |
| **Cut unnecessary moving parts (`session.bin`, `LISTEN_FDS`, `startup.err`, IPC `Ping/Pong`)** (GPT M1/M2, Claude M1/M4, Kimi M1/M2, GLM M1/M13, 10th H4/M1) | `session.bin` wrote 512 KiB of unencrypted peer chat to disk (backed up by Time Machine!) for a 55s convenience; `LISTEN_FDS` risked signaling `systemd --user`/`launchd`; `startup.err` duplicated the readiness pipe; IPC `Ping/Pong` fed spurious reconnect kills. | **CUT ALL FOUR.** Deleted `session.bin`, `LISTEN_FDS`/`launch_activate_socket`, `startup.err`, and IPC `Ping/Pong`. Recovery always uses the single authoritative path (`GET /v1/accounts/me` + fresh `PARTY_SNAPSHOT` + durable `epochs.bin`). |
| **Ghost party member & unreachable `ControlPersist` idle exit** (Claude H10, 10th M2) | Eager `d.sock` connect from every open IDE tab kept `connected_clients >= 1` forever; active party with zero attached clients stayed online indefinitely as a ghost member. | **FIXED.** `mp-outpost mcp` connects lazily on first `tools/call` and drops idle `d.sock` after `120s` when `active_parties == 0`. When `connected_clients == 0` while in a party, daemon emits Lane 2 `ephemeral_pulse(idle)` and detaches/leaves after configurable `unattended_party_timeout_secs` (default `1800s`). |

### 2. P2P Data Plane, Party Scoping & Control-Plane Correctness

| Finding (Reviewers) | Root Cause in v1 | v2 Disposition |
| --- | --- | --- |
| **Multi-party `iroh::Endpoint` policy conflict, cross-party routing ambiguity & relay flapping** (All 5: Kimi C3/C4, GPT C2/C3, Claude C2, GLM H6, 10th C4) | One daemon-global `iroh::Endpoint` cannot mix `allow_relays`, `force_relays`, and `no_relays`; Blackbird wire has no `party_id`; two endpoints with one `device_pubkey` kick each other off `iroh-relay`; `no_relays -> force_relays` was unchecked. | **FIXED.** Enforce **1 active party per `device_id` in v1** (matching Blackbird's `P2pPartySession`; operators needing 2 concurrent parties enroll a 2nd device out of 8). Construct `iroh::Endpoint` **lazily per party** with exact `effective_policy` + `pinned_relay_url` and tear down on leave/disband. Enforce symmetric join/create compatibility matrix (`force_relays <-> no_relays` rejected in both directions; local policy is non-downgradeable floor). |
| **CWT -> TLS RPK -> Pinned `root_pubkey` binding gap** (Claude C3, GPT H4) | Admission gate checked snapshot membership, CWT validity, and account pin separately without asserting `TLS RPK == snapshot.device_pubkey == CWT.cnf.x` and `CWT.iss == hex(sha256(PINNED_root_pubkey))`. | **FIXED.** Explicitly lock the 5-link verification chain: `TLS 1.3 RPK -> snapshot.device_pubkey -> CWT.cnf.x -> CWT.iss -> PINNED peers.bin root_pubkey` (never trusting snapshot `root_pubkey` for pinned accounts). |
| **Blackbird wire mismatches (`p2p_party_session.hpp`, `blackbird-p2p` Stream 0 ACK / `4409`, `MessageReceipt`, `bridge_envelope`)** (GPT C11, Claude C7/H2, 10th H3, GLM M9) | Spec v1 listed a 2-byte header instead of Blackbird's 4-byte header, omitted Stream 0/4 `u32::MAX` init/ack handshake and close code `4409`, invented a phantom Lane 1 `MessageReceipt`, and assumed Outpost could sign SSH-keyed `BoardBridge` envelopes. | **FIXED.** Locked Spec v2 to Blackbird Wave 11B's exact 4-byte header + all 4 frame kinds + golden hex vectors (`xplat-board` `seq: 14`) + Stream 0/4 `u32::MAX` handshake + close codes `4000/4400/4401/4403/4409/4413` + deterministic dial recovery (single-flight dialer, `peer trust` kicks dial loop, newest-wins `4409`). Removed phantom Lane 1 `MessageReceipt` (use Lane 0 `control_notice(sync_ack)` + local per-client cursor). Scoped v1 `bridge_envelope` (`0x02`) as raw opaque bytes pass-through until joint Ed25519 BoardBridge signing is defined with `blackbird-leader`. |
| **Static `MP1:PONG` vs revocation lease, sleep-blind `Instant`, server `clock_offset_ms` abuse, WS `404`/`403`, dual-host `device_id` flapping & `PARTY_ENDPOINT_UPDATE` churn** (GPT C4/H6/H7, Claude H5/M6/M7, Kimi H5/H6/H7, GLM H5) | `MP1:PONG` auto-response doesn't wake `PartyDO`; `Instant` pauses during laptop sleep; applying server `clock_offset_ms` to peer CWTs lets a compromised server accept expired CWTs; retrying `404`/`403` loops forever; `watch_addr()` churn blows the 2/min+burst-4 budget. | **FIXED.** (1) Use sleep-aware clocks (`CLOCK_BOOTTIME` Linux / `mach_continuous_time` macOS) for all lease/liveness/idle timers. (2) Keep `MP1:PONG` strictly as transport liveness + cap authorization at exact local & peer CWT expiry deadlines using local system clock ONLY (`clock_offset_ms` applies ONLY to outbound RFC 9421 signing for `api_authority`!). (3) Classify `404`/`403` WS upgrade failures as terminal. (4) Detect rapid `<60s` session eviction loops -> `device_id_in_use_elsewhere` alert + pause P2P. (5) Coalesce `PARTY_ENDPOINT_UPDATE` to `<= 1/30s`, honor `retry_after_ms`, emit zero updates under `force_relays`, and preserve `Idempotency-Key` across transport retries while minting fresh RFC 9421 nonces per attempt. |
| **Hand-rolled HTTP/1.1 + RFC 6455 WS client** (All 5: Kimi C9, GPT C10, Claude H8, GLM H4, 10th H1) | ~350 LOC omitted chunked transfer encoding, post-`101` TLS buffer carryover, WS fragmentation, interleaved control frames, masking, and close handshakes — while `iroh 1.5.0` ALREADY compiles `hyper 1.12` + `tokio-websockets 0.13` unconditionally! | **FIXED.** Reuse `hyper 1` (HTTP/1.1 client) + `tokio-websockets 0.13` (already in `iroh`'s `Cargo.lock` — **zero new transitive crates**) over our own TLS 1.3-only `tokio-rustls` stream (explicitly rejecting redirects, `permessage-deflate`, non-`mp1` subprotocols, and `> 16 KiB` REST / `> 8 KiB` aggregate WS messages). |

### 3. Security Boundaries, Trust UX, Persistence & MCP Stdio

| Finding (Reviewers) | Root Cause in v1 | v2 Disposition |
| --- | --- | --- |
| **Honest UID trust boundary, cold `.root` placement & TTY-gated `peer trust`** (All 5: Kimi C2, GPT C1, Claude C4, GLM C2, 10th C2) | Self-declared `client_kind` on `d.sock` cannot stop a same-UID agent with shell access; storing `.root` in predictable `<state_dir>/roots/` made it hot; non-interactive `--safety-number` argv let an injected agent copy the SN from `party_members` and pin a MitM key. | **FIXED.** (1) State the honest same-UID boundary in §1.2 and drop fake `client_kind` ACL enforcement on `d.sock` (keep as diagnostic telemetry; MCP tool exclusion is an LLM guardrail). (2) Do NOT store `.root` in `<state_dir>` by default — require explicit `--root-key-out <path>` on `account register` with offline-custody warning (primary workflow: enroll from Blackbird host via `device init` + `device install-cwt`). (3) Make `peer trust` and `peer revoke` **strictly interactive `/dev/tty`**, deleting `--safety-number` from argv. |
| **Unpinned-peer broadcast DoS, Safety Number ambiguity & server handle resolution** (All 5: Kimi C10, GPT H4/H5, Claude H1/H3/H4, GLM H3/M5, 10th H2) | 1 unpinned newcomer froze `party_send` for pinned teammates; Safety Number said "Crockford (or hex)"; no `whoami --safety-number`; `PARTY_SNAPSHOT` lacks `handle` (payload `sender_handle` is spoofable!). | **FIXED.** (1) Unify `party_send` and `board_post`: `key_mismatch` fails closed hard; targeted send checks target pin only; broadcast delivers to `pinned_trusted` connected peers (refusing only if `0` pinned recipients) and returns explicit `{ delivered_to[], withheld_unpinned[], disconnected[] }`. (2) Lock ONE Safety Number format: first 20 bytes of `SHA-256("mp-safety-v1:" || account_id_le64 || root_pubkey[32])` -> 32 uppercase Crockford Base32 chars (`8 x 4` groups), add `mp-outpost whoami --safety-number`, and propose adopting the same formula with `blackbird-leader`. (3) Fetch display handles lazily from `GET /v1/accounts/<id>` (never trust payload `sender_handle`), always pairing with integer `account_id`. |
| **Provenance fence breakout & crown-jewel secret scanner** (Claude C8/M5, GLM C3/C4, GPT H9, Kimi H8/H9, 10th H3/M5) | JSON `\u003c` decoded back to `<` before LLM saw it; stripping all C0 killed `\n`/`\t`; scanner missed our own `device_secret`/`device_cwt` while false-positiving on protocol docs. | **FIXED.** (1) Use per-response CSPRNG nonce fence `<<<BLACKBIRD_UNTRUSTED_PEER_DATA_BEGIN_<16hex>>>>` ... `<<<BLACKBIRD_UNTRUSTED_PEER_DATA_END_<16hex>>>>` + deterministically mangle any decoded occurrence of `<<<`/`>>>`/the nonce; preserve `\n` and `\t` while stripping other C0/C1/ESC/BiDi/zero-width; separate provenance from content in `structuredContent`. (2) Exact-match our own `device_secret` and `device_cwt` (raw + hex + base64 + base64url) + exact-grammar `mpinv1_<43b64u>`, `mppi1_<digits>_<43b64u>`, and `-----BEGIN * PRIVATE KEY-----`; label honestly as an accidental-disclosure guard. |
| **Durable `epochs.bin`, locked `peers.bin`, crash-safe registration & CWT hot-reload** (Kimi C7, GPT C5/H8, Claude H12/H14, GLM M4, 10th H3/H5) | `highest_seen_epoch` vanished on crash; `peers.bin` lacked a lock file; registration had no pre-POST journal for response-loss recovery; `device init` had no pre-ID filename; `install-cwt` lacked `pop_verified` probe & daemon reload. | **FIXED.** Serialize state files under `<state_dir>/state.lock`; persist bounded `epochs.bin` (`[(party_id, highest_epoch, terminal_flag)]`, max 64 entries) durably before processing roster updates; add `pending_reg.bin` & `pending_dev.bin` staged journals preserving `Idempotency-Key`; `device install-cwt` verifies `CWT.cnf == local_device_pubkey`, probes `GET /v1/accounts/me` to flip `pop_verified = 1`, and notifies running daemon to reload CWT. |
| **IPC frame caps, `(daemon_epoch, after_seq)` cursors, honest `delivery_unknown`, multi-window isolation, Linux `socketpair` `ENXIO` & approval CLI** (Kimi C5/C6/C8/M4/M7/M8, GPT C8/C9/H10/H11, Claude C5/C6/H6/H7/H9/M8/M9, GLM H2/M7/M8/M14, 10th H3/M4) | 1 MiB IPC cap couldn't fit 1 MiB `bridge_envelope` or 100 chats; bare `after_seq` deafened agents after restart; in-RAM `client_msg_id` wasn't restart-safe; Linux `/proc/self/fd/0` fails `ENXIO` on libuv `socketpair`s; approval-mode CLI was missing; `board_read` was missing. | **FIXED.** (1) Raise IPC frame cap to `2 MiB`; byte-budget `party_poll` (`512 KiB` default, always `>= 1` event); cap live ring at `512` events / `8 MiB`. (2) Require `(daemon_epoch, after_seq)` cursor (all MCP JSON integers `<= 2^53 - 1`); return `{ cursor_reset: true, gap_possible: true, daemon_epoch, next_seq }` on epoch change; per-client read cursors (no cross-window unread clobbering). (3) Shim generates `client_msg_id`, rejects hash mismatch on live reuse, and returns `delivery_unknown` honestly on mid-send daemon restart. (4) Use one uniform blocking `stdin` reader thread + serialized `stdout` writer task on BOTH macOS and Linux, exiting via `std::process::exit(0)` on EOF. (5) Add `board_read` MCP/CLI tool and `party requests | approve | reject` CLI commands. |
